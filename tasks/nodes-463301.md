Both trusted publishers — PyPI nodes-core and npm @nodes-dev/core — name the repository nodes-dev/core, which is where this project lived until it moved to verifiably/nodes. Workflow release.yml and environment release are both still correct; only the owner and repository are stale.

This breaks the next release. A GitHub OIDC claim carries the repository path at run time, so the workflow now asserts verifiably/nodes while the publisher expects nodes-dev/core, and the registries match that field literally. GitHub's redirect from nodes-dev/core is live but irrelevant: redirects apply to git and the web UI, not to claim matching.

Nothing has been published since 2026-07-18, when both nodes-core 0.1.1 and @nodes-dev/core 0.1.1 went out from the old path, so the config was right when it last worked and has been stale ever since.

Fix on both registries: add a publisher for verifiably/nodes, keeping release.yml and release, then remove the nodes-dev/core one. Add before removing — PyPI allows several — so there is never a window with none.

No hijack exposure: the nodes-dev organisation still exists with khughitt as admin and zero repositories, so nobody else can create nodes-dev/core and inherit the trust. That would change if the organisation were ever deleted or transferred, which is its own reason to remove the entry rather than leave it.

Independent of nodes-77c7cc: this corrects a broken path, whereas the package-name change belongs with the rename.
