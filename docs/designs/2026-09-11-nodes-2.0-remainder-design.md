This is the umbrella over the reviewed redesign's unimplemented deltas. It rules how they
land as one 2.0 surface, splits them into sub-tasks, and fixes the boundaries between
those sub-tasks. It adds no contract of its own: each sub-task's brainstorm owns its
contract, and `docs/STANDARD.md` remains normative.

## 2. Integration strategy

**One branch, one merge.** All work lands on `nodes-2.0` (worktree `.worktrees/nodes-2.0`)
and merges to `main` with `--no-ff`, so the 2.0 surface appears at exactly one commit.
Beliefs consumes `nodes-core` by editable path from `main`'s tree and uses none of the
withdrawn surface, so the branch is invisible to it and the merge is drop-in.

**Version discipline on the branch.** STANDARD's header keeps `1.2` and gains one line:

> **Pending:** 2.0 amendment in progress on branch `nodes-2.0`; clauses marked *(2.0)*
> are not yet in force.

Every sub-task edits its STANDARD sections and fixtures in the same commit as its code,
marking each edited clause *(2.0)* — §12's same-change rule holds per commit. Each commit
also keeps the standard internally consistent: a withdrawal removes every cross-reference
to the withdrawn surface, and a fixture owner updates its §11.2 inventory row at once.
The amendment sub-task (E) bumps the header, writes the §12 history entry, strips the
markers, removes the pending line, and reconciles the final inventory. `main` therefore
only ever reads 1.2 or 2.0.

### A — reserved paths and containment (redesign §2.2)

**Implementation status (2026-09-11):** implemented on branch `nodes-2.0`; see
`2026-09-11-nodes-reserved-paths-and-containment-design.md`. Science sign-off on the
write-plan seam amendment remains pending.

Contract: nodes never reads, writes, or deletes non-`*.md` content under the root, with
one explicit exception — its own reserved cache namespace, which already holds JSON
snapshots and vectors. The reserved list is closed and versioned in the standard (today
exactly `.nodes-index/`). A's brainstorm decides whether `.nodes-index` is reserved
root-relative only (today's TypeScript reading) or at any depth (today's Python
first-component reading is root-relative too; the difference is what a nested
`a/.nodes-index/` means). Traversal: no walk follows a symlink — file or directory, at any
depth — and every yielded path resolves within the root. Both walks propagate filesystem
failures instead of dropping subtrees: Python's `rglob` suppresses `PermissionError` and
TypeScript's walk catches `readdirSync` errors, so A replaces both with explicit
`scandir`/`readdirSync` recursions that raise. (CPython 3.11's recursive glob already
declines to follow directory symlinks; the walk change is about errors, not traversal.)

Traversal containment alone does not deliver the non-Markdown guarantee during mutation.
`PlanRefusedError` is lexical (escaping or reserved paths); `DefaultExecutor` then writes
with `write_bytes` through whatever sits at the path, so a create onto a dangling symlink
(which passes the `exists()` precondition) or a replace of a `.md` that became a symlink
after construction reaches its target outside the root. A owns both halves of the
contract: the standard states the walk guarantee and the executor's physical containment
separately, and `DefaultExecutor` gains a pre-effect check — no path component below the
root, and no target, is a symlink (`lstat`, not `stat`) — a whole-plan preflight refusing
with `ExecutionError(index=i, applied=0)` before any effect; the same check guards
`Store`'s direct read, write, and delete paths, which bypass the executor. The check is a preflight: it detects a symlink that exists at check
time and does not guard against a concurrent replacement between check and write, which
the single-writer rule already excludes. That is an amendment to a seam part Science exercises (create), so it
goes through seam §8's amendment log with consumer sign-off; A's brainstorm drafts the
entry.

### C — digest-shaped ids (redesign §2.4)

**Well-placed.** A member is *well-placed* when its physical root-relative path equals
`path_for(id)` exactly. Today nothing verifies this at construction: a misplaced file is
accepted into the index and then unreachable by `get()`, which reconstructs the path
from the id. Two members *collide* when their mapped paths — `path_for` of their ids, not
their physical paths — are equal under NFC + casefold, or equal exactly through the
`:` → `__` mapping (`kind:a:b` vs `kind:a__b`). Both definitions are C's; B consumes them.

**Ownership.** C owns collision detection, mutation refusal, and the `path-collision`
finding; B owns what construction does with misplaced and colliding files (§B). One
helper computes collisions for `assert_addable` (add and reconcile), `rename`, and
`check`, so construction can report rather than refuse. Its signature is C's brainstorm's
to choose, under two requirements the bare `(candidate id, existing paths)` form cannot
meet: it must carry the candidate's uid so that a same-`(uid, id)` add remains the
permitted replacement it is today (`corpus.py:178`), and it must give an explicit rule for
a **same-path rename** — old and new ids differ but their mapped paths collide (a
case-only rename). Ignoring the shared uid would admit it, and its create-then-delete plan
is unsuitable on a case-insensitive volume: today the create's existence precondition
refuses it there before any effect, and a plan that passed that precondition would delete
the one physical file. C picks between refusing it and emitting a
distinct in-place plan for it. `rename` today checks only `resolve_uid(new_id)`
(`corpus.py:277-280`); routing it through the helper is implementation work in C.

Rules: `assert_addable` and `rename` refuse a candidate that collides with an existing
member; `check` reports `path-collision` for corpora that already contain one. Strict
construction **accepts** a collided corpus whose claimants are all well-placed — two
distinct files are a valid corpus on the filesystem that holds them, and refusing would
make Linux-built corpora unopenable — and `check` reports the latent hazard. Walk order
already uses Unicode code-point collation in both kernels (STANDARD §4.1), matching §8.2
and §9.1; A delivered TypeScript's `compareCodepoints` walk sort. C owns the STANDARD
wording and Python/TypeScript parity for any remaining sorts. The uid-minting SHOULD
becomes an opacity statement.

**Fixtures.** A collided corpus at rest with well-placed claimants is not checkout-portable
(case-variant filenames), and the `__` form cannot exist at rest at all (one physical
path). C's brainstorm therefore chooses between constructing the casefold pair in-test
on case-sensitive volumes and committing claimants at distinct physical filenames, which
are by construction misplaced and exercise B's `path-mismatch` path as well. Refusal of a
second add or a colliding rename needs only one existing file and is portable either way.

### B — collecting construction (redesign §2.3, amended)

Entry: a constructor flag (`Corpus(root, mode="collecting")` / `{mode: "collecting"}`);
strict remains the default. An unparseable or structurally invalid file becomes a
`parse-error` finding (severity error) plus an excluded member; a duplicate uid becomes
one corpus-level `uid-collision` finding and excludes **all** claimants; `check()` is
the single reporting surface and folds construction findings in. Mutation on a
collecting corpus is allowed. B's brainstorm settles, at minimum:

- the finding's `ref` when parsing yields no id (path-anchored, since no id exists);
- **misplaced members** (§C's well-placed rule): strict construction refuses them — reads
  cannot reach them — and collecting mode excludes each with a path-anchored finding, by
  default a distinct `path-mismatch` code rather than a widened `parse-error`;
- **colliding members**: well-placed claimants stay ordinary members under both modes
  (they are readable and, on that volume, mutable); `check` carries C's finding. B states
  this explicitly so that no claimant is ever half-admitted;
- that an excluded file can never become an overwrite target — `add`/`rename` must
  treat excluded paths as occupied, not free;
- behaviour across snapshot load, `flush_index`, and reopen (excluded members are not in
  the manifest; whether findings persist or re-derive on reopen);
- registry-backed `check()` iterating accepted members only — today it re-reads every
  file through `store.all_nodes()`, which would re-raise on the excluded ones;
- filesystem failures stay exceptions, distinct from content findings (A makes both
  walks propagate them; B keeps the line for construction findings);
- the fixture: a committed damaged corpus and oracle pinning `parse-error`,
  `uid-collision`, and (from C) `path-collision` in one `check` output, plus strict
  construction's refusal of the same tree.

Beliefs is the first consumer (its audit and manifest boundaries); B's brainstorm reads
those designs for the expected consumer shape before fixing the API.
